## 1. Why it was terminated

The termination is **not** a computation failure, an implementation failure, or a resource
problem. The A0.1 record is unambiguous on that point: zero addendum cells were run, all
1,086 tests passed, and the projected cost was only 8.573 CPU core-hours
(`S0B_FINAL_GATE_REPORT.md:894-911`, the block now marked superseded in its §9.1). What was left were design and estimand defects that no
amount of computing can close:

1. **No single stable prespecified estimand.** D16 makes "the contrast in `relative_log_gap`
   as defined in D14" the primary statistic, but D14 defines that quantity *per arm*, and
   neither ruling says whether the contrast is the difference of the two arms' per-arm ratios
   or the raw contrast divided by one common denominator, at which level the division
   happens, or whether the primary pools the three `delta_eta` levels
   (`S0B_NORMALIZED_CONTRAST_SENSITIVITY.md:71-104`).
2. **Reasonable normalizations reverse the direction.** See §2.
3. **The inferential-unit premise behind ruling D13 is false.** See §3.
4. **The paper does not need it.** Simulation 1A (exact enumeration, `d = M`) carries the
   dense-signal behaviour; Simulation 1B carries the finite-sample sparse-signal design at
   `d = 3` in every cell; Simulation 1C isolates the binary-width mechanism under
   position-specific and Hamming-weight targets and tests shared-value versus column-aware
   hashing directly. Those three arms, plus Simulation 2, are the paper's simulation scope.

Running the addendum *after* it was known that the choice of normalization changes the sign
would have forced the authors to pick an estimand and a normalization with the answer already
in view. That is an avoidable researcher degree of freedom, and avoiding it is the reason for
terminating rather than executing.

## 2. Evidence — three normalizations that disagree in direction

in the aggregation choice. Regenerated by
`scripts/s0b_normalized_contrast_sensitivity.py --reps 50` (fits no learner, executes zero
addendum cells).

So the per-arm family spans **−0.018 to −0.020** and is negative in every member; the two

a reading D16's wording never explicitly forbids
(`S0B_NORMALIZED_CONTRAST_SENSITIVITY.md:190-213`). One unwritten sentence decides the sign of
the result. That is a specification defect, not a measurement.

## 3. Evidence — the false premise behind the inferential unit

Advisor ruling D13 fixed block-clustered inference on "the 8 independent parameter-draw
blocks with 7 degrees of freedom", justified as a **fact about the code**: that the DGP
parameters are drawn once per block and reused across the 50 replicates. That fact is false.

**Code path (line numbers re-checked against the current tree for this record):**

| file:line | what it establishes |
|---|---|
| `scripts/run_sim1b_dense_addendum.py:343-355` (`addendum_seed`) | `SEED_BASE_1BD + 1000 * (blake2b(repr(block)) % 1e6) + int(replicate)` — **the replicate index is folded into the seed**; one seed per `(block, replicate)`. |
| `scripts/run_sim1b_dense_addendum.py:421` | `seeds=[addendum_seed(blk, r) for r in range(1, REPS_ADD + 1)]` — every scenario carries 50 distinct seeds. |
| `scripts/run_sim1b_dense_addendum.py:1037` | `for rep, seed in enumerate(seeds, 1):` — the replicate loop. |
| `scripts/run_sim1b_dense_addendum.py:1039-1040` | `prm = CORE.draw_params(..., seed, d_active=D_ADD)` — **`draw_params` is called INSIDE the replicate loop with the replicate-varying seed. This is the decisive line.** |
| `src/ct2i_benchmark/simulations/sim1_core.py:132-153` (`draw_params`) | `rng = np.random.default_rng(seed)`, then `a = rng.standard_normal((d, K))` and one `rng.standard_normal((K, K))` per interaction pair — a different seed gives a different `a` and `b`. |
| `tests/test_a0_dense_addendum_properties.py:437` (`test_replicate_still_varies_the_draw`) | the repository's own frozen property test already asserted `not np.array_equal(p1.a, p2.a)` across replicates. |

**Measured (`S0B_D13_PREMISE_INVESTIGATION.md:99-106`, `:131-139`, `:274-291`):**

| quantity | measured | what D13's premise predicts |
|---|---|---|
| within-block replicate pairs examined (8 blocks × 6 pairs, `delta_eta = 0.0`) | **48** | — |
| pairs whose parameter arrays are identical (`max\|Δa\|` exactly 0.0) | **0 / 48** | 48 / 48 |
| min / max over those 48 pairs of `max\|a(r1) − a(r2)\|` | 1.521143 / 4.561064 | 0 / 0 |
| distinct seeds, and distinct `(a, b)` byte signatures, per arm | **400 / 400** (8 blocks × 50 replicates, no collisions) | 8 |

So there are **400 independent parameter draws per arm, not 8**. The only cluster is
`(block, replicate)`, with 6 members (3 `delta_eta` × 2 `n_train`), and the 8 blocks are a
complete, exhaustively enumerated 2×2×2 factorial of **fixed** design factors, not a random
sample from a population of blocks. D13 was stated as a fact about the parameter draws rather
than as an estimand choice, so it is superseded by the verification above rather than reopened
as a design question. Treating the eight blocks as fixed factors and the parameter draw as the
inferential unit remains available to any future analysis that wants it.

The unit is not cosmetic: it moves `t` by a factor of 1.5–2.3 without touching the estimate
(`S0B_NORMALIZED_CONTRAST_SENSITIVITY.md:165-171`), and D16's E1 clauses are one-sided tests
whose outcome classes convert a null into a reported conclusion, so an inflated SE
manufactures `NOT_SUPPORTED` verdicts.
